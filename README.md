# ppt-builder

一个 WorkBuddy 技能：把一堆材料变成一份**能上评审台**的中文汇报 PPT。

不是提示词模板，是「五阶段流程 + 三个脚本 + 一套实测量出来的版式规格」。
LLM 直接生成 PPT 的通病是字号小到看不清、每页塞满、满屏占位框、图注比正文长——
这个技能把这些约束前置成流程和代码，让第一稿就接近定稿。

---

## 它长什么样

一份 14 页的项目申报汇报，正文 18–24pt、最小 16pt、每页主讲 180–280 字、
图注不超过 14 字、零占位框、表格只留必核列。
版式是 33.87 × 19.05 cm（16:9）的固定网格，红色结构色 `#B52525`，微软雅黑。

规格全部来自对一份真实定稿 PPT 的逐形状量测，不是估的。见
[`references/01-visual-spec.md`](references/01-visual-spec.md)。

---

## 五阶段，三道门

| 阶段 | 做什么 | 门禁 |
| --- | --- | --- |
| **S0 收料** | 读材料，列出「缺失信息」与「口径冲突」两张清单，**不猜** | 本阶段禁止建文件 |
| **S1 大纲** | 一页一行的表：页码 / 标题 / 所属章 / 副标 / 呈现形式 / 图表 / **这页要证明什么** | ⛳ 用户确认后才往下 |
| **S2 逐页稿** | 先给 3 页样例看语气，通过后批量产出。每页三层：L1 说明、L2 页面文案、L3 演讲备注 | ⛳ 用户确认 |
| **S3 图表表格** | 每张图 7 项：图号 / 所在页 / 位置尺寸 / 纵横比 / 数据出处 / 统计口径 / **缺哪年数据** | 可与 S2 同批确认 |
| **S4 模板解析** | 有模板就解析出骨架；没有就用内置骨架，不再追问 | 输出「继承 / 偏离」对照表 |
| **S5 成稿** | 生成 → 自检 → 渲染逐页看 → 出 PDF | `qc_deck.py` 必修项清零 |

两个门禁是硬性的：**大纲没确认不写正文，正文没确认不生成 PPT**。
跳过门禁的结果是返工，这个技能不省这一步。


## 30 秒验证

```bash
cd ~/.workbuddy/skills/ppt-builder
pip install python-pptx

python scripts/build_deck.py assets/example_spec.json -o demo.pptx
python scripts/qc_deck.py demo.pptx
```

`assets/example_spec.json` 是一个 7 页的完整示例（封面、目录、三列配图、
六段流程、表格页、四卡配图、结束页），数据是虚构的，照抄改字就能用。

自带样图在 `assets/samples/`，都是虚构数据画的，可直接替换。

## 三个脚本

| 脚本 | 用途 | 说明 |
| --- | --- | --- |
| `scripts/analyze_pptx.py 某模板.pptx` | 拆模板 | 输出画幅、跨页重复的骨架构件、字号分布、配色。识别"哪些版位是常量" |
| `scripts/build_deck.py spec.json` | 生成 | 按 JSON 生成整份 PPT。**自带版式预警**：文本估算超框时会喊，不必等渲染才发现 |
| `scripts/qc_deck.py 成品.pptx` | 自检 | 扫字号下限、元素越界、页码位置、占位残留、表格行高、图文重叠 |

```bash
python scripts/build_deck.py spec.json -o 汇报.pptx
python scripts/analyze_pptx.py 参考模板.pptx
python scripts/qc_deck.py 汇报.pptx
```

## spec.json 怎么写

一页一个对象，`type` 决定版式。七种页面类型：

| type | 用途 |
| --- | --- |
| `cover` | 封面（标题 / 项目类别 / 落款三行） |
| `toc` | 目录（6 条编号） |
| `tri` | 三列观点 + 下方三张图 + 通栏 |
| `flow` | 中心句 + 横向链条 + 2×2 产出块 |
| `table` | 表格 + 右侧或下方说明栏 |
| `blocks` | 2×2 卡片 + 底部 1–2 张照片 |
| `end` | 结束页 |

完整字段见 [`references/06-spec-schema.md`](references/06-spec-schema.md)。
`assets/example_spec.json` 是最好的参照。

一条铁律：`notes` 是**演讲备注**（进 PPT 备注栏），`footnotes` 是**页面表注**（画在页面上），
两个键不能混用——混了会按字符炸出几十个文本框。

## 内置版式规格（节选）

| 项 | 值 |
| --- | --- |
| 画幅 | 33.87 × 19.05 cm |
| 页标题 | 34pt 加粗，L 2.77 / T 0.52 |
| 副标 | 24pt 加粗 `#B52525`，写法 `1、xxx` |
| 正文 | 18–24pt，**全篇禁止 < 16pt** |
| 内容区 | 左 1.70 / 右 32.10（可用宽 30.40） |
| 三列网格 | 宽 9.55，起点 1.70 / 12.02 / 22.34 |
| 页码 | 16pt `#9A9A9A` 右对齐，L 30.40 / T 17.90 |
| 底部线 | 满宽 33.87，T 18.80，单条 `#B52525` 1.0pt |
| 表格 | 表头红底**只保留横线**，行高下限 = 字号 × 1.30 × 0.0353 cm |
| 对齐 | 左对齐。两端对齐会让含数字的行出现大空隙 |

**放不下时的判断顺序：删字 → 删列 → 删页 → 最后才考虑降字号。**
反过来做（先降字号）是最常见的失败模式。

## 文案规则（节选）

六类改写，都是从真实返工里总结出来的：

| 动作 | 反例 | 正例 |
| --- | --- | --- |
| 去机理修饰，一句一个判断 | 「非常规饲料原料营养价值数据不足，抗营养因子与毒素影响其稳定利用」 | 「非常规饲料原料数据不足，高效利用不足」 |
| 删「标签：值」前缀 | 「人才称号：xxx」「科研奖励：xxx」 | 直接陈述，靠红竖条和字重分层 |
| 虚词换硬数 | 「发表多篇论文」 | 「论文 40 余篇、专利 19 项」 |
| 单元格短语化 | 「样品处理至结果判读不超过 2 小时」 | 「小于 2 小时」 |
| 合并同类条 | 一页四条并列 | 三条，把次要的并进别页 |
| 图注只做索引 | 「图2 生猪养殖成本构成（2024年）·国家发改委汇编」 | 「图1 生猪养殖成本核算」 |

**无出处的图不画。** 人名、职称、单位、项目名、金额，材料里没有就列进
「待本人确认」，不在页面上留空也不按常识补。

## 关于这个仓库

**不含任何真实项目数据。** 模板 `assets/template.pptx` 是 0 页纯骨架
（母版 + 13 个版式，96 KB），示例数据全部虚构，样图用假数据生成，
logo 需自备。原因很直接：原始模板里有真实姓名、电话、成员名单与经费明细，
那些不该进公开仓库。

骨架之所以能这么小，是因为 `build_deck.py` 只从模板继承母版、主题和画幅，
页面内容由 spec 生成——模板里的页面对它毫无用处。

---

## 已知限制

- 只做中文、桌面 16:9。其他比例要改顶部常量。
- 版式是固定的 7 种。超出这个范围的排法需要改 `build_deck.py` 的渲染函数。
- 溢出预警按字符数估算，**最终必须渲染出来逐页看**，估算替代不了肉眼。
- 单页 > 300 字说明这页该拆，脚本不会替你拆。
